# Dashboard — Business Intelligence Layer

The BI layer turns the warehouse semantic layer into portable business
deliverables. It has three complementary parts:

| Part | Location | What it is |
|------|----------|------------|
| **Outcome report** | `dashboard/reports/project_outcome.html` | Standalone HTML report with KPIs, trends, product/regional/customer analysis, quality, pipeline health, and lineage |
| **BI extracts** | `dashboard/exports/*.csv` | One CSV per analytical view or monitoring table, plus `kpi_summary.json` and `manifest.json` |
| **Live control center** | `dashboard/web/index.html` | Operations dashboard served by FastAPI at `/` |
| **Tool setup guides** | `dashboard/powerbi/`, `dashboard/tableau/` | Binding instructions and field documentation for Power BI and Tableau |

The CSV + HTML approach is deliberate: it is reproducible on any machine,
works with the SQLite fallback warehouse, and can be loaded into Power BI,
Tableau, Excel, or a notebook without a live database connection. Binary
`.pbix` / `.twbx` workbooks are **not** generated by this repository.

## Quick Start

```powershell
# From the project root, with the virtual environment active
python scripts/setup_database.py
python scripts/run_pipeline.py --pipeline etlt_plus_plus --source csv `
  --file tests/fixtures/sample_transactions.csv --dataset transactions
python scripts/load_warehouse.py

# Build the BI deliverables
python scripts/export_bi_data.py
python scripts/generate_project_report.py --open

# Serve the report and exports through the API
uvicorn api.main:app --port 8000
```

Open:

- `http://localhost:8000/reports/project-outcome` — generated report
- `http://localhost:8000/api/v1/bi/exports` — export manifest (JSON)
- `http://localhost:8000/exports/analytics_v_daily_sales.csv` — direct download
- `http://localhost:8000/` — live pipeline control center

Or simply run `python scripts/showcase.py`, which runs a pipeline, ensures the
warehouse is populated, exports the BI data, generates the report, and starts
the server.

## Generated Datasets

`python scripts/export_bi_data.py` writes these files to `dashboard/exports/`:

| File | Source | Grain |
|------|--------|-------|
| `analytics_v_daily_sales.csv` | `analytics.v_daily_sales` | One row per calendar day |
| `analytics_v_product_performance.csv` | `analytics.v_product_performance` | One row per current product |
| `analytics_v_regional_analysis.csv` | `analytics.v_regional_analysis` | One row per location/region |
| `analytics_v_customer_segments.csv` | `analytics.v_customer_segments` | One row per current customer |
| `analytics_v_transaction_detail.csv` | `analytics.v_transaction_detail` | One row per transaction line |
| `monitoring_pipeline_metrics.csv` | `monitoring.pipeline_metrics` | One row per pipeline execution |
| `monitoring_batch_quality_metrics.csv` | `monitoring.batch_quality_metrics` | One row per validated batch |
| `monitoring_alert_log.csv` | `monitoring.alert_log` | One row per alert |
| `metadata_lineage_events.csv` | `metadata.lineage_events` | One row per pipeline stage event |
| `kpi_summary.json` | Computed | Headline KPIs in a single JSON document |
| `manifest.json` | Computed | Generated files, row counts, columns, backend, errors |

Use `--limit N` to cap rows per dataset (useful for quick tool previews) and
`--output-dir PATH` to write elsewhere.

### KPI summary contents

`kpi_summary.json` contains:

- Revenue, transactions, units sold, average order value
- Active customers, product count, region count, date range
- Top product, top region, top category and category breakdown
- Quality scores: freshness, completeness, accuracy, contract adherence, overall
- Pipeline runs, success rate, average duration, last execution
- Alert totals by severity
- Warehouse row counts (staging, dimensions, fact)

The HTML report and any BI tool can consume the same numbers, which keeps the
story consistent across deliverables.

## Option A — Connect Power BI / Tableau to the CSV Extracts (recommended offline)

1. Run `python scripts/export_bi_data.py`.
2. In Power BI: **Get Data → Text/CSV →** select all files in `dashboard/exports/`.
   In Tableau: **Connect → Text file →** select the CSVs.
3. Promote the first row to headers (Power BI does this automatically).
4. Define relationships on the documented keys:
   - `analytics_v_product_performance.product_id` ↔ `analytics_v_transaction_detail.product_id`
   - `analytics_v_customer_segments.customer_id` ↔ `analytics_v_transaction_detail.customer_id`
   - `analytics_v_daily_sales.full_date` ↔ `analytics_v_transaction_detail.transaction_date`
5. Refresh by re-running the export script and hitting **Refresh** in the tool.

This path needs no database driver and works in the SQLite fallback mode.

## Option B — Connect to PostgreSQL / Snowflake Directly

| Setting | Value |
|---------|-------|
| Host | `localhost` (dev) / `<production-host>` (prod) |
| Port | `5432` |
| Database | `pipeline_warehouse` |
| User | `pipeline_user` |
| Schemas | `analytics` (views), `warehouse` (tables), `monitoring` (metrics) |

Use DirectQuery / Live connection only when PostgreSQL is available; otherwise
use the CSV path. See [`powerbi/README.md`](powerbi/README.md) and
[`tableau/README.md`](tableau/README.md) for step-by-step setups and DAX /
calculated-field definitions.

|-------|-----------|---------|

## Validation Checklist

```powershell
# 1. Exports exist and are non-empty
python -c "import json; m=json.load(open('dashboard/exports/manifest.json')); print(m['backend']); [print(d['name'], d['rows']) for d in m['datasets']]"

# 2. KPI summary is valid JSON
python -c "import json; print(json.load(open('dashboard/exports/kpi_summary.json'))['revenue'])"

# 3. Report renders
start dashboard/reports/project_outcome.html

# 4. API serves the assets
python -c "from fastapi.testclient import TestClient; from api.main import app; c=TestClient(app); print(c.get('/api/v1/bi/exports').status_code, c.get('/reports/project-outcome').status_code)"
```

Expected: every analytics view has rows after a warehouse load, the KPI summary
parses, the report opens with charts and tables, and both API calls return 200.

## Notes and Limitations

- The report and exports reflect whatever is currently in the warehouse. Run a
  fresh pipeline and warehouse load before a formal demo if you need current
  data.
- Monetary values are presented in Indian Rupees (₹) because the sample dataset
  is India-based; the pipeline and schema are currency-agnostic.
- The SQLite fallback attaches all schemas to one file, so `analytics.*`,
  `warehouse.*`, and `monitoring.*` queries behave like a single database.
- Power BI and Tableau binaries are intentionally not shipped; the CSV
  extracts, field documentation, and connection guides are the portable,
  reviewable substitutes.
